# Paymentology Credit

A static interactive article about how credit can adapt to unstable economic conditions: one HTML page with CSS, vanilla JavaScript (no framework), and static images and fonts.

Preview: https://pw-paymentology-credit.vercel.app/ (hidden from search engines, see [Search indexing](#search-indexing))

## Getting started

Node.js and npm are required.

- Install dependencies: `npm install`.
- Serve the source version locally: `python3 -m http.server 8000`, then open `http://localhost:8000`.
- Create a production build: `npm run build`.
- Preview the production build: `python3 -m http.server 8000 --directory dist`, then open `http://localhost:8000`.

## Project structure

| Path | What it is |
|---|---|
| `index.html` | The article markup |
| `css/article.css` | All styles. Edit this file |
| `js/article.js` | All behaviour: charts, animations, interactive photo. Edit this file |
| `css/article.min.css`, `js/article.min.js` | Generated by the build. Do not edit |
| `public/img/` | Images used by the page (webp, plus `og.jpg`) |
| `public/fonts/` | The four woff2 fonts referenced from the CSS |
| `scripts/minify.mjs` | The build script |
| `dist/` | Production build output, committed for convenience |
| `vercel.json`, `.vercelignore` | Vercel deployment settings |
| `robots.txt` | Copied into `dist/` by the build |

## Build

`npm run build` runs `scripts/minify.mjs`, which:

1. Clears and recreates `dist/`.
2. Minifies `index.html`, `css/article.css` and `js/article.js` into `dist/`.
3. Writes the same minified CSS and JS to `css/article.min.css` and `js/article.min.js`. `index.html` loads the `.min` files, so the local source preview always runs the latest code.
4. Copies `public/` (without `.DS_Store`) and `robots.txt` into `dist/`.

HTML whitespace is collapsed conservatively on purpose: mobile CSS hides `<br>` in headings, and without the kept space words around a `<br>` would merge.

## How the page works

### Sections

- **Hero and graphic-0** — header image and world map card (`initGraphic0`).
- **Chart 1 (US) and chart 2 (Europe)** — SVG charts drawn by `drawChart1` and `drawChart2`, mounted by `mountChart`. Charts redraw when the layout breakpoint or width changes. Each redraw aborts the previous draw's listeners, observers and timers through an `AbortSignal`.
- **Graphic-3** — the photo of Maya with pins and popups (`initGraphic3`). Pin keys (`expense`, `employment`, `credit-history`, `income`, `shock`, `spending`, `access`) link three things: the `.hs-*` position classes in CSS, the popup copy in the `popups` object in JS, and the `data-key` attribute in HTML.
- **Quotes, title, copy, Read more** — reveal animations (`initQuotes`, `initArticleTitle`, `initCopyFade`, `initReadMore`).
- **Glass decorations** — parallax images on desktop only, at least 861px wide (`initGlassParallax`). Their real `src` is set by JS from `data-src`.

The mobile layout applies at `max-width: 860px`.

### Animations and fallbacks

Copy is revealed with scroll animations. They are designed so the text is never lost:

- `<html>` starts with the `no-animate` class, which shows everything without animation.
- An inline script in `<head>` removes `no-animate` before the first paint, unless the browser lacks `IntersectionObserver` or the user prefers reduced motion.
- `js/article.js` sets `window.articleReady = true` at the end. If the script fails to load or throws, the inline script restores `no-animate` on `DOMContentLoaded`.
- `prefers-reduced-motion: reduce` turns off the reveal sequences and the idle pin and dot pulsing. CSS also cuts the remaining transitions.
- Printing switches to `no-animate`, so the whole article is printed.
- URL parameters for testing: `?animate=no` turns animations off, and `?mobileanimate=no` turns them off at mobile widths only.

### Accessibility

- Graphic-3 pins, chart 1 annotation points, chart legends and the chart 2 slider work from the keyboard. Focus shows a popup, Enter or Space keeps it open, and Escape closes it. The slider uses the arrow keys, Home and End.
- Focus rings show for keyboard focus only (`:focus-visible`).
- The chart SVGs use `role="group"`, so their controls are exposed to screen readers. Annotation points and the slider have spoken labels with the values.

## Images

Only the files used by the page are in `public/img/`. Source images (high-resolution PNG and JPG, unused fonts) are kept outside the repo in `src-img/`, which is ignored by git and Vercel. Ask the project author if you need them.

The responsive webp files were made with `cwebp`, for example:

```bash
cwebp -q 80 -m 6 -sharp_yuv -resize 1200 0 src-img/g3.png -o public/img/g3-1200.webp
```

Graphic-0 and graphic-3 come in 800, 1200, 1800 and 2400 px widths. On mobile the graphic-3 photo is about 1.85× the viewport width, which is why its `sizes` is `(max-width: 860px) 185vw, 1250px`.

## Hosting on the hub

Copy the **contents** of `dist/` into any folder on the server, for example `/credit-article/`. All paths in the page are relative (`css/…`, `js/…`, `public/…`), so the article runs from the domain root or from any folder. Tested from a sub-folder on desktop and mobile: no missing files and no script errors.

The page must be opened with the trailing slash: `/credit-article/`, not `/credit-article`. Without it, relative paths point one level too high and styles, scripts and images fail to load. A script at the top of `<head>` redirects to the address with the slash, keeping the query and hash, but the browser may already have requested a file from the wrong place by then. **Set up a server-side redirect** from `/credit-article` to `/credit-article/` so this never happens.

## Deployment

The Vercel project builds every push to `main` as a production deployment, running `npm run build` and serving `dist/`.

`vercel.json` also sets these headers. They apply to Vercel only, so set equivalents on the hub:

- `X-Robots-Tag: noindex, nofollow` on every response.
- `Cache-Control: public, max-age=31536000, immutable` for `/public/fonts/`.
- `Cache-Control: public, max-age=86400, stale-while-revalidate=604800` for `/public/img/`. Image file names are not hashed, so they are not cached for long.

## Open items before going live

### "Read more" link has no destination

The call-to-action button at the end of the article points nowhere:

```html
<a class="read-more" href="#">Read more <span aria-hidden="true">→</span></a>
```

The target URL was not available when the page was built. JS (`initReadMore`) only animates the button and does not set the link.

**To do:** replace `href="#"` with the real URL. If it should open in a new tab, add `target="_blank" rel="noopener"`. Then run `npm run build`.

### Search indexing

The Vercel deployment is a preview, so it is hidden from search engines in two ways:

- `robots.txt` contains `Disallow: /`.
- `vercel.json` sends `X-Robots-Tag: noindex, nofollow`.

`index.html` itself has no `noindex` meta tag, so the page markup can be reused as is.

**To do when hosting on the hub:** do not carry over the `Disallow: /` rule or the `X-Robots-Tag` header to the production site.

### Social card image, og:url and canonical need the final URL

`index.html` already has `og:type`, `og:site_name`, `og:title`, `og:description` and `twitter:card`. The tags that need an absolute URL were left out because the final address is not known yet. The card image is ready: `public/img/og.jpg`, 1200×630.

**To do:** add these to `<head>` with the real address of the article:

```html
<link rel="canonical" href="https://EXAMPLE.COM/ARTICLE-PATH" />
<meta property="og:url" content="https://EXAMPLE.COM/ARTICLE-PATH" />
<meta property="og:image" content="https://EXAMPLE.COM/ARTICLE-PATH/public/img/og.jpg" />
<meta property="og:image:width" content="1200" />
<meta property="og:image:height" content="630" />
<meta property="og:image:alt" content="Glowing world map on a purple background" />
```

### No favicon

The page does not reference a favicon, so browsers request `/favicon.ico` and get a 404. There is no suitable brand icon in the repo.

**To do:** add the hub's favicon, for example:

```html
<link rel="icon" href="/favicon.ico" sizes="32x32" />
<link rel="apple-touch-icon" href="/apple-touch-icon.png" />
```
